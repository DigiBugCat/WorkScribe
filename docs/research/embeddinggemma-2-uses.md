# EmbeddingGemma 2: how people are repurposing it

Survey date: 2026-10-13 (model released 2026-10-06, so this is one week of community work).
Scope: what others have built on `google/embeddinggemma-2`, not our own experiments. The speaker-ID benchmark is running separately.

## How to read the evidence labels

- **Verified (card)** means I read the Hugging Face model card or GitHub README myself. The numbers are the author's own claims, and nobody re-ran them. The card says what was done, which doesn't make the result true.
- **Verified (leaderboard)** means the number shows up in a third-party leaderboard (`LocalLLaMA/typed-decisions`). The leaderboard marks most fine-tuned rows as self-reported.
- **Secondary** means it came from a blog, news article, or search-result summary, and I couldn't read a primary source.
- **Tweet-only** means I saw it only as an X search snippet. X needs a login, so I couldn't open any thread.

I couldn't open X directly because search redirects to login. The X items here come from search-engine snippets. I found no X post about speaker ID or diarization with EG2.

---

## TL;DR for WorkScribe

1. **Local meeting software is an active product category.** Compare public product claims without assuming implementation details.
2. **The "decision" trend is a typed-decision head on the EG2 text tower.** You give it a state, typed questions (`choice` / `noul`=bool / `score`) and options, and it returns calibrated probabilities in one forward pass with no generation. Three independent EG2 fine-tunes land at 74–76% on `LocalLLaMA/typed-decisions`, against a teacher ceiling of about 73.5%. Google's MediaPipe *Decision Maker* task does the same thing zero-shot, and it accepts audio as state or options.
3. **Nobody has published speaker-ID or diarization results with EG2 audio embeddings.** The audio tower has been repurposed for ASR (CTC readers), sound events, and voice emotion, all of which are content or paralinguistic tasks. The closest signal for speaker work is Reflex-2's 8-class voice-emotion probe on unseen speakers: 14% raw, 52% with a linear head. That suggests the pooled embedding carries some voice-level information, but it's weak.
4. **Apple deployment is well trodden.** There are several Core ML and Core AI ports, some with text on the ANE, plus MLX and MLX-Swift runtimes. Audio runs at 617x real time on an M5 Pro GPU and an hour-long earnings-call index has already been built. There's also a Core ML port of the typed-decision model.

## 1. Decision / classification heads ("System One" models)

Context: a wave of "typed decision" models followed TypeSafe's *Jev* API (`noul`/`choice`/`score` primitives). The community benchmark is [`LocalLLaMA/typed-decisions`](https://huggingface.co/datasets/LocalLLaMA/typed-decisions): 400 test cases, 2,000 decisions, and synthetic workflows covering customer service, invoices, security incidents, and agent traces. Gold labels average three samples from a ~4B teacher, and teacher self-agreement is **0.735**. Scores well above that mean the model is learning the teacher's quirks.

**Takeaway on the "decision" trend.** The EG2 text tower (270M) plus a sub-1M head is a credible local classifier for typed judgments. A frozen head gets about 68% and end-to-end fine-tuning gets about 75–76%, all against a 73.5% teacher ceiling. The key engineering ideas are text options (so the schema can change without retraining), soft-label loss, and per-type temperature calibration for abstention. None of these projects used meeting data. The closest are glance-v1 (samsum dialogue) and qnaug (intent and NLI).

## 6. Gotchas that kept coming up across cards

- **Never run it in fp16.** Activations reach about 2,000, and RMSNorm overflows into NaN or silently bad vectors. Core ML ports fix this with max-abs-rescaled RMSNorm. Use bf16 or fp32 otherwise.
- **The ANE needs fixed shapes.** Flexible or enumerated shapes fall back to CPU and run 30–40x slower. On Core ML the audio conformer's chunked attention leaves the ANE, so FluidInference runs it on the GPU, while EverPaper's Core AI port keeps it on the ANE.
- **Audio input:** mono 16 kHz at 25 tokens/s. The model maxes out at about 327 s per call, but most ports cap at 10–30 s windows.
- **Zero-shot "audio ↔ text label" judgments are weak.** Reflex-2 measured 14–54% raw versus 52–96% with a linear head. Expect to train small heads.
- **Calibration doesn't transfer.** Every decision-model author says to re-fit temperatures on a few hundred in-domain examples.
