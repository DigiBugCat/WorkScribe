# Lean proofs for WorkScribe's pure state machines

Machine-checked proofs about four pieces of WorkScribe that are pure functions of their inputs:
the AI line lifecycle, the auto-record policy, the audio backlog counters, and three small
policies. The concurrent parts are covered separately by TLA+ (`formal/tla`).

**What a proof here means.** Every theorem is about a Lean re-implementation of the Swift, not
about the Swift itself. A theorem is worth exactly as much as (a) the Lean definition matches the
Swift it names, and (b) the statement says something you care about. For (a), each definition
carries the Swift file and lines it transcribes, the Swift text is quoted next to it, and
`Tests/WorkScribeCoreTests/FormalConformanceTests.swift` runs the real types against the same
statements. For (b), each theorem has one plain sentence above it.

**Second round.** The first round proved that two places in the Swift broke invariants the rest
of the code relies on, and that the auto-record start latch could stick. All three were then
changed in the Swift. This version describes the changed code: the two broken invariants now hold
with no exception, the latch has a proved way out, and what the fixes do not cover is listed under
[Findings](#findings).

## Defects these proofs found, now fixed

### A published image result hid an answered line

- **What the defect was.** The publish path of `readNoteImages` wrote `state = .listening` over
  every line the user did not own, including one that still had its text. The first round proved
  the state/text invariant `WF` false for it (`imagePublish_breaks_wf`, now gone).
- **What a user would have seen.** An answer that was on screen disappeared when a late OCR
  result or a caption for the same jot arrived, because the Obsidian plugin never draws the text
  of a `.listening` line (`obsidian-plugin/src/ui/surfaces/line.ts:12-18`, read). It came back at
  Stop.
- **The fix.** `Line.recheck()` (Line.swift:27-31) clears `queryText` and only sends a line with
  no text back to `.listening`; the publish path (NoteImageUnderstanding.swift:116-122) calls it,
  or `reset()` for an image-only note whose images carry no evidence.
- **What guards it now.** `wf_step` / `wf_run` / `wf_reachable` hold for all fourteen operations
  with no exception, and `text_never_hidden_reachable` says it in screen terms. `recheck_keeps_answer`
  and `imagePublish_keeps_answer` are the direct statements; `captionTrace_keeps_answer` and
  `lateOcrTrace_keeps_answer` are the two traces that used to fail. The old publish code is kept
  as `Broken.imagePublish` with an `example` that it violates `WF` on both traces. In Swift:
  `testImageResultKeepsAnAnsweredLineVisible`, `testLateImageResultKeepsAnAnsweredLineVisible`.

### A changed image list cleared the line without telling the revision or the history

- **What the defect was.** `NoteDocument.notes(previous:)` set the text to nil when a note's image
  list changed, but left the revision and the history as they were. "A text change raises the
  revision" was false for it (`docImagesChanged_clears_text_without_bump`, now gone).
- **What a user would have seen.** If the engine regenerated the same sentence after the image
  change, it was rejected as a repeat of the history (`LineCheck.accept` → `.quiet(.flap)`,
  Line.swift:143), so the line stayed empty for good. Separately, a draft written before the
  change still matched the line's revision and could be applied over it.
- **The fix.** The branch now calls `reset()` on a line the user does not own
  (NoteDocument.swift:74).
- **What guards it now.** `text_change_bumps_rev` holds for all fourteen operations with no
  exception, and `text_change_bumps_rev_run` extends it to whole sequences.
  `docImagesChanged_not_owned` says the path is exactly `reset()`; `docImagesChanged_bumps_rev` and
  `docImagesChanged_trace_bumps_rev` give the revision; `docImagesChanged_allows_previous_text`
  says the cleared sentence is accepted again; `docImagesChanged_outdates_drafts` says the old
  revision is never matched again. The old code is kept as `Broken.docImagesChanged` with an
  `example` that it violates both. In Swift, on the real method:
  `testDocumentImageSyncStartsTheLineOverAndRaisesTheRevision`.

## Findings

Ordered by how much a user would notice. "Proved" means a Lean theorem; "read" means I traced the
Swift or plugin source and did not execute it. None of these is an invariant that the fixes left
broken: after modelling the new code, `WF` and "a text change raises the revision" hold on every
path. They are limits of what the fixes reach, and behaviour that was not touched.

### 1. After a manual stop, the next call is not recorded if it starts within the grace period (hazard (e)(ii), TRUE, unchanged)

- **Proved:** `suppressed_until_long_absence`. After `suppressCurrentCall()`, for as long as no
  run of call-absent samples reaches `endGraceSeconds` (120 s), every action is `.none`. The
  policy has no notion of which call is active. `startDidNotBegin()` does not help: it is ignored
  while the policy is suppressed (`startDidNotBegin_suppressed`, `suppression_lifted_only_by`).
- **Counterexample trace** (also a Lean `example` and
  `testFindingACallStartingWithinTheGraceAfterAManualStopIsNeverRecorded`): call A recorded, the
  user stops by hand at t = 1800 s, A ends, call B begins 60 s later and runs two hours. B is
  never recorded. With a 130-second gap it is.
- **What the user sees:** back-to-back meetings less than two minutes apart; the second one is
  silently not recorded. The same holds after a failed automatic start (AppModel.swift:349), a
  refused captions start (AppModel.swift:365) and a mid-recording failure (`fail` → `stop()` →
  AppModel.swift:443) (read).

### 2. The start latch: stuck under `update` alone, released by `startDidNotBegin()` (hazard (e)(i))

- **Still true of `update` alone:** `stuck_latch`. Once `.start` is returned, every later
  call-active sample returns `.none`, for any values of `busy` and `automaticallyRecording`.
- **The way out, proved:** `stuck_latch_released`. After `startDidNotBegin()`, a call that is seen
  active at `t0`, is active at every later sample, and is seen active and not busy at some
  `t1 ≥ t0 + settleSeconds` gets `.start` again (`start_again_after_startDidNotBegin` is the same
  from any policy that is not suppressed; `start_fires_after_startDidNotBegin` is the two-sample
  form). The latch theorem (b) now lists five releases: `second_start_needs_release`.
- **It must settle anew, proved:** `start_after_startDidNotBegin_settles_anew`. The run of
  call-active samples that justifies the new `.start` lies entirely after the
  `startDidNotBegin()`; time the call was active before does not count.
- **What the fix does not give:**
  - *A limit on attempts.* `start_fires_after_startDidNotBegin` applies again to its own result,
    so with a `startDidNotBegin()` after every attempt one call gets a `.start` every time it has
    settled again (three in sixteen seconds in the Lean `example`). How often the app asks is now
    up to the caller.
  - *Anything for a suppressed policy.* A start that failed has already called
    `suppressCurrentCall()`; the report that it did not begin is then a no-op, and finding 1
    applies.
  - *A statement about the app.* The policy method is modelled as an event that may arrive at any
    time. That `AppModel` calls it on every path where an automatic start returns without a
    recording is read, not proved: AppModel.swift:181-186 calls it after `start` returns unless
    this call's recording is running; the paths that reach it un-suppressed are the entry guard
    (:208-209, another start in progress, quitting, or busy) and the two resume refusals (:229,
    :231).
- **Note, proved:** on every reachable policy the `guard !suppressed` in `startDidNotBegin()`
  changes nothing, because a suppressed policy already has an open latch and no candidate
  (`startDidNotBegin_guard_redundant`). The guard is harmless. Removing it in the scratch copy
  made no conformance test fail, as this predicts.

### 3. What the image-result fix does not reach

- **A line that is already hidden stays hidden (proved, `hidden_line_from_old_build_not_repaired`).**
  A `.listening` line that holds text, as the old publish path wrote it, is decoded from disk
  exactly as saved (Notes.swift:48). `recheck()`, a further image result, the found marking and
  `resume()` leave it not well formed (`wf_recheck_iff`, `wf_imagePublish_iff` give the exact
  condition). `settle()` (Stop), `reset()` and an `apply` with `.unchanged`/`.quiet` repair it,
  as before (`wf_settle_any`, `wf_reset_any`, `wf_apply_noline_any`). Since Stop settles every
  line, this only concerns a meeting that the old build left interrupted in that state.
- **An image result after Stop un-settles a line without text (proved, minor).**
  `image_result_after_stop`, `settle_then_recheck`, `imagePublish_stays_stopped_iff`: a `.quiet`
  line goes back to `.listening`, and the `.settled` line of an image-only note that now has no
  evidence is reset; a `.settled` line otherwise stays `.settled` with its text. Read: image
  results can arrive between Stop and finalize (the reader runs on a document sync,
  LocalAPI.swift:137, and is cancelled at finalize, MeetingNotes.swift:201); the plugin then
  stops showing "Not discussed" for that jot; the publish schedules an engine pass
  (NoteImageUnderstanding.swift:125) and a pass on a stopped meeting ends by settling every line
  again (MeetingNotes.swift:288, 309).
- **Whether the engine actually looks again (found by reading, then fixed).** The first version
  of `recheck()` cleared `queryText` and left `basis`. For a jot with words, FindNotes.swift:59
  targets a note again only when `basis == nil` or there is new relevant transcript evidence, and
  `basis` was set by the earlier answer, so a late image result did not reliably lead to a new
  answer. `recheck()` now clears `basis` as well (`recheck_not_owned` states the exact record
  update, and FormalConformanceTests checks the Swift method against it). What is proved is the
  field being cleared; that FindNotes then targets the note is read from the code at that line,
  not proved or tested end to end.

### 4. Smaller ones

- **"Revision increases exactly when the text changes or ownership is taken" is false in one
  direction (benign).** `reset()` on a line with no text also raises it
  (`reset_bumps_without_visible_change`). The exact rule for the eight `Line` methods is
  `rev_increase_iff`. The image publish raises it on every line (`imagePublish_rev`), by design.
- **A changed image list does not raise the revision of an owned line**
  (`docImagesChanged_bumps_rev`, `yours_docImagesChanged`), while an image result does
  (`yours_imagePublish`). Drafts are never applied to an owned line (CurrentNoteEngine.swift:30,
  read), so nothing follows from the difference.
- **`resume()` erases the answer-note marker (minor).** MeetingNotes.swift:57 starts a note made
  from an answer at `.quiet`; `resume()` turns that into `.listening`, identical to a fresh jot
  (`resume_erases_answer_marker`). The engine still skips such notes (`fromAnswer == nil` filters),
  so the effect is at most a "listening" marker during a resumed recording; I did not confirm that
  such a note is drawn through `linePresentation`.
- **Two unused doors.** A bare `takeOwnership()` / `owned = true` on an empty line gives an owned
  line with no text, and `owned = false` gives an `answered` line whose text is not in its
  history. Nothing in `Sources/` calls either today; `ownedHasText_reachable` and
  `textInHistory_reachable` state exactly what holds without them.
- **`.settled` and `.quiet` are not terminal:** a later `apply` un-settles them
  (`settled_not_absorbing`), and so does `recheck()` for a line without text (finding 3).
- **`.stop` repeats** on every later absent sample while the recording is still marked automatic
  (`stop_repeats`); `AppModel.stop` is idempotent, so this is only a note.

### Checks that came out fine

- MeetingNotes.swift:57 (`.quiet` for a note made from an answer) keeps the invariant: `wf_new`.
- `editEnhancement` keeps the invariant, and the stronger "an owned line has text":
  `wf_editEnhancement`, `ownedHasText_reachable`.
- Both image paths and the listening → found marking keep the invariant: `wf_step`.
- `recheck()` commutes with `resume()` and does not change what a later Stop decides:
  `recheck_resume_comm`, `recheck_then_settle`.
- `startDidNotBegin()` does not interrupt an absence run, so the grace period that stops an
  automatic recording is unaffected: `inv_step` with `Event.KeepsAbsence`, and a Lean `example`.
- All backlog invariants hold; none was false.

### `Formal/AutoRecord.lean`

A trace is a list of `Event`s: `update(…)`, `suppress`, `reset`, `startDidNotBegin`.
`ActiveSince es t` says the trace ends with an unbroken run of enabled call-active samples
containing one taken at `t`; nothing else may follow that sample. `AbsentSince es t` is the same
for call-absent samples, except that `startDidNotBegin` events may lie in the run, because that
method leaves `absentSince` alone. All of this mirrors C/AutoRecordPolicy.swift:5-43.

### Checks against vacuity

Each module ends with a `Checks` section: `example`s showing the hypotheses used above are
satisfiable on concrete values, and `Broken.*` definitions (each marked WRONG ON PURPOSE) with an
`example` that the broken variant violates the invariant. Examples: `settle` that always says
`.settled` breaks `WF`; `apply` without the history guard breaks `HistDistinct`; `update` without
the latch returns two `.start`s in a row; `acknowledge` without the clamp makes both counters
negative; a split that drops the remainder loses bytes.

The two operations as they were before the fixes are among them: `Broken.imagePublish` takes a
well-formed answered line to `.listening` with its text on both traces, and
`Broken.docImagesChanged` changes the text with no revision increase and then rejects the
sentence it cleared. Also new: `Broken.recheck` (always `.listening`) breaks `WF`, and
`Broken.startDidNotBeginKeepsCandidate` returns `.start` two seconds after a failed attempt.

## Where the model abstracts or differs from the Swift

Everything not listed is transcribed as written.

### All modules

1. Mutating methods are functions from the old value to the new one. A method that mutates and
   returns a value returns a pair.
2. Swift `Int`/`Int64` is unbounded `Int`. Swift traps on overflow; the model does not.
3. Operations are applied one at a time to one value. Which sequences the app can actually
   produce, and anything about actors, tasks or locks, is outside these models. The theorems
   quantify over all sequences, which is more than the app can do.

### Line (`Formal/Line.lean`)

4. `String` is one abstract type `Text` with decidable equality, used for line text, `queryText`,
   `basis`, evidence ids and the jot. No string operation is modelled.
5. `Date` is `Nat` and is never compared. `Note.createdAt: Double?` is `Option Nat`.
6. `LineRevision.reason: String` is a two-value enum for the two literals at Line.swift:45.
7. `LineOutcome.line(Bullet, [String])` is `.line markdown ids` because `apply` reads only
   `bullet.markdown`. `.quiet(LineRejection)` carries no payload because `apply` never reads it.
8. `retract(remaining:jot:)`: `remaining.isEmpty` and the result of `LineFaithfulness.grounded(…)`
   are two `Bool` arguments. Nothing is proved about the grounding check itself.
9. `version: revision ?? 1` (Line.swift:45) is the value assigned on line 43, which is never nil.
10. The `owned` getter is declared `Bool?` and never returns nil; modelled as `Bool`.
11. `Note` keeps `text`, `createdAt`, `line`, `queryRevision`, and `fromAnswer` as a `Bool`;
    `id`, `section`, `surface`, `trace`, `images` are dropped.
12. `editText`: tokenising (`LexicalMatcher.tokens`) and the set arithmetic are not modelled;
    `major` is a `Bool` argument. The rule itself is `Note.isMajorEdit`, where the `Double` test
    `difference / max(1, union) > 0.3` is written as `10 * difference > 3 * max 1 union`. That
    rewriting is not proved in Lean; the Swift test checks it for all counts up to 400.
13. `editEnhancement` takes `value.markdown` instead of a `NoteEnhancementText`.
14. `Note.new` is `Note(text:createdAt:)` followed by MeetingNotes.swift:56-57 as one constructor.
    The `fromMissedTopic` branch (MeetingNotes.swift:59-63) is `editEnhancement` plus an
    unmodelled write to `line.evidence`.
15. `markFound`: the id and `queryRevision` parts of the predicate (which note) are dropped.
16. `recheck`: the two statements after the guard (`queryText = nil`, then
    `if text == nil { state = .listening }`) are written as one record update.
17. `imagePublish`: `isImage` and `imageEvidence.isEmpty` are `Bool` arguments rather than derived
    from the note; the guard (note found, image found, result differs) is dropped, since nothing
    is written when it fails; the write to the image itself (line 114) is dropped with `images`.
    The Swift changes a copy of the line and writes it back; the model returns the new line.
18. `docImagesChanged` is only the one line write inside `if (n.images ?? []) != images`. The
    rest of `notes(previous:)` (an `editText` before, `editEnhancement`/`letAIRewrite` after) is a
    sequence of modelled operations, not modelled as one.
19. Not modelled: `Codable` decoding including the legacy migration (Notes.swift:38-60), so a
    line loaded from disk is assumed to have been produced by these operations (finding 3 is
    about a line that was not); `lineNeedsEvidence`; `CurrentNoteEngine.apply`'s guards and its
    writes to `attemptedEvidence` and `seenThrough` (CurrentNoteEngine.swift:34-35);
    FindNotes.swift:64 (`seenThrough` on a request copy); Replay.swift:112 (`.listening` on a
    fresh note, which changes nothing); `SearchIndex.saveLines`.

Write sites to a line's fields outside `Line.swift`, checked again on 2026-11-11 by search:
NoteImageUnderstanding.swift:116-122 and NoteDocument.swift:74 (modelled), MeetingNotes.swift:57
and :269 (modelled), Notes.swift:23, 26, 31 (modelled as `editText`, `editEnhancement`,
`letAIRewrite`), Replay.swift:112, Notes.swift:50-58, CurrentNoteEngine.swift:34-35,
MeetingNotes.swift:61, FindNotes.swift:64 (the last five as in item 19).

### Auto-record (`Formal/AutoRecord.lean`)

20. `Date`/`TimeInterval` are `Nat` seconds. Fractional seconds are not in the Lean model (the
    Swift test uses them).
21. `now.timeIntervalSince(x) >= s` is written `x + s ≤ now`.
22. `if x == nil { x = now }` followed by `x!` is written `some (x.getD now)`.
23. `settleSeconds` and `endGraceSeconds` are fields with the Swift defaults; theorems hold for any
    values (the "does fire" theorems that return `.none` first need `settleSeconds` or
    `endGraceSeconds` positive).
24. `busy` and `automaticallyRecording` are arbitrary inputs on every sample. The model does not
    tie them to what `AppModel` does with the returned action, and does not model the early
    returns in `checkCall` (AppModel.swift:168-172) that skip a sample.
25. `startDidNotBegin` is an event that may occur anywhere in a trace. The model does not tie it
    to a preceding `.start` or to the outcome of the app's `start`.
26. "Continuously" always means "at every sample taken". For absence, calls of
    `startDidNotBegin()` between samples do not count as an interruption (`Event.KeepsAbsence`),
    because the method does not touch `absentSince`; for activity they do, because it clears
    `candidateSince`.

### Backlog (`Formal/Backlog.lean`)

27. `Data` is `List α`; `count` is `length`.
28. `failure: Error?` is the `Bool` `failed`. Which error is thrown is not modelled.
29. Each `lock.withLock` body is one atomic step; the lock is assumed to work.
30. `next()` is one pass through its locked section, with a fourth result `wait` standing for
    "sleep 20 ms and try again". Cancellation is not modelled.
31. `AudioBacklog` is a class; the model is a value.
32. `pendingSeconds` and `VoiceAudioWindow` (lines 61-83) are not modelled.

### Small (`Formal/Small.lean`)

33. `RecordingPressure(lag:)`: `Double` is any type with a decidable `≤`; transitivity of `≤` is a
    hypothesis of the theorem. `message` is dropped.
34. `Meeting` keeps nine properties; `Date` is `Int` seconds; `document?.finalized` is one
    `Option Bool`; `throws` is `Option`; the default `now = Date()` is dropped. The cleared
    dictionaries `partials`, `partialSpeakers`, `partialIDs` are dropped.
35. `RecordingSession` keeps `isInitial` (`id == "initial"`), `start`, `end`; ids,
    `sourceOffsets`, `screen` are dropped.
36. `TitlePolicy.canGenerate` takes `titleOrigin`, `titleFinal` and the word count of line 8 as a
    number; `excerpt` and `clean` are not modelled.

## Not proved (inconclusive, not dropped)

1. **Whether the engine looks again after `recheck()`** (finding 3). It depends on
   FindNotes.swift:59 and Enrich.swift:103-105, which are app code. Read, not modelled, not run.
2. **That a stale draft is rejected.** The proofs give the premise: after either image event the
   revision never returns to its old value (`imagePublish_outdates_drafts`,
   `docImagesChanged_outdates_drafts`). The guard that compares revisions
   (CurrentNoteEngine.swift:29) and the order in which a draft and an image event reach the main
   actor are app code and concurrency, outside this model.
3. **That the app reports every start that did not begin** (finding 2). `startDidNotBegin` is
   proved as a policy method. Its one caller (AppModel.swift:181-186) was read, not modelled; in
   particular nothing here shows that the condition it tests (`busy` and the meeting's trigger)
   is right on every path of `AppModel.start`.
4. **How often the app retries one call** now that the policy does not limit it (finding 2).
5. **That a line un-settled by an image result after Stop is settled again** (finding 3): read
   from the scheduler, not modelled. The plugin rendering was also read, not run.
6. **Whether finding 4's answer-note marker is ever drawn.**
7. **Real-valued time.** The Lean policy uses whole seconds. The properties are about order and
   addition and I expect them to hold for `Double`, but that is not proved; the Swift test uses
   fractional steps.
8. **The 0.3 rule for more than 400 tokens** (item 12). The two forms can only disagree when the
   ratio is within one rounding step of 0.3, which needs about 10^15 tokens; that argument is not
   formalised.
9. **`Double`'s `≤` is transitive** (item 33): assumed.
10. **Liveness in general.** Three "it does fire" results are proved (`start_fires_after_settle`,
    `stop_fires_after_grace`, `stuck_latch_released` with its two forms). Finding 1 shows "an
    active call is eventually recorded" is false in general; no exact condition for it is stated.
11. **Lines loaded from disk** (item 19), including legacy notes whose history comes from the
    old trace format, and lines the old build saved hidden (finding 3 says what does and does not
    repair one; how many exist is unknown).
12. **The write sites in the app target** (`markFound`, `imagePublish`, MeetingNotes.swift:57)
    are transcribed into the Swift test, because the test cannot import the app.
    `testTranscribedCodeStillMatchesTheSource` now fails when the first two change as text;
    MeetingNotes.swift:57 and anything they call are not covered by it.
13. **The conformance test under SwiftPM.** It was compiled and run with `swiftc`/`xctest` against
    a copy of the core sources, not with `swift test`.
